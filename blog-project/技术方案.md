> 从 WordPress（Qzdy 主题）迁移而来的独立博客，纸感编辑风，代码开源。

| 项目 | 说明 |

| 认证 | NextAuth | ^4.24.15 | 凭证登录 + JWT session |

| Markdown 增强 | remark-gfm / rehype-slug | — | 表格、任务列表、标题锚点 |

- 字体走 **@fontsource 本地包**，国内网络无需访问 Google Fonts。

## 三、系统架构

```
┌────────────────────────────────────────────────────────────┐
│  Next.js 16 (App Router)                                   │
│                                                            │
│  前台 (blog)     管理后台 (admin)     登录 /login            │
│  ├─ 页面组件 (RSC, ISR/SSG)        ├─ (admin) layout 守卫   │
│  └─ Client 组件 (交互)             └─ Client 组件 (CRUD)    │
│                     │                      │                │
│            ┌────────┴──────────────────────┴───┐            │
│            │      NextAuth /api/auth/[...]     │            │
│            │        (Credentials + JWT)        │            │
│            └───────────────┬───────────────────┘            │
│                            │                               │
│            ┌───────────────▼───────────────────┐            │
│            │  Hono 应用  app.basePath('/api')   │            │
│            │  posts / shiyu / comments / search │            │
│            └───────────────┬───────────────────┘            │
└────────────────────────────┼───────────────────────────────┘
                             │ requireAdmin() 写操作守卫
                    ┌────────▼────────┐
                    │   PostgreSQL    │
                    │  (Prisma 7)     │
                    └─────────────────┘
```

**请求流转**
1. 前台读操作 → RSC 直连 Prisma 查库（SSG / ISR 缓存），或走 `/api/*`（拾语翻页、阅赞）。
2. 后台写操作 → Client 组件 `fetch('/api/*')` → Hono 路由 → `requireAdmin()` 校验 ADMIN → Prisma 写入 → `revalidatePath()` 刷新前台缓存。
3. 认证 → `/api/auth/[...nextauth]`（NextAuth 的路由比 Hono 的 catch-all 更具体，优先匹配，互不干扰）。

## 四、数据模型

`prisma/schema.prisma`，5 张业务表 + 1 张多对多关联表 + 1 个枚举。

```
User ─┬──< Post (authorId)      Tag >──< _PostToTag >──< Post
      ├──< Comment (authorId)   Comment ──> Post (postId)
      └──< Shiyu  (authorId)
```

### Post（文章）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | String cuid | 主键 |
| title / slug | String | slug 唯一，`github-slugger` 生成 |
| excerpt | String? | 摘要 |
| content | String | MDX 正文 |
| coverImage | String? | 封面 URL，未填时后端随机取预设 |
| published | Boolean @default(false) | 发布状态 |
| views / likes | Int @default(0) | 浏览 / 点赞计数 |
| readingMinutes | Int | **发布时按正文长度算好入库**（`calcReadingMinutes`），列表查询免拉正文 |
| createdAt / updatedAt | DateTime | 时间戳 |
| authorId | String | 关联 User |

索引：`@@index([published, createdAt])` —— 前台列表与统计走组合索引。

### Tag（标签）
- `name` / `slug` 唯一；随文章表单逗号分隔自动 upsert，**无需单独维护**。

### User（用户）
- `email` 唯一；`username` 唯一（可空，凭证登录支持「账号或邮箱」）。
- `password` 可空 —— 仅凭证登录用户有；访客评论按邮箱 find-or-create，无密码不可登录。
- `role` 枚举 `USER | ADMIN`（默认 USER）。

### Comment（评论）
- `published` 默认 true（schema），但业务上访客提交一律 `false` 待审，后台审核。
- `ip` 可空 —— 仅存于后台（限流 + 审核展示），不对公网暴露。
- 索引：`@@index([ip, createdAt])` —— 5 分钟 IP 限流查询。

### Shiyu（拾语）
- `no` Int —— 流水序号，新建时 `max(no)+1`，前台展示 `N°xxx`。
- `images` String? —— **JSON 数组字符串**，序列化/反序列化在 `lib/shiyu.ts` 完成。
- `pinned` 置顶、`published` 发布状态。
- 索引：`@@index([published, createdAt])`。

### 迁移历史
| 迁移 | 内容 |
|---|---|
| `20260811065515_init` | 建表：Post / Tag / User / Comment / Shiyu + _PostToTag + Role 枚举 + 索引 + 外键 |
| `20260811073355_add_shiyu_no` | Shiyu 加 `no` 流水号 |
| `20260811090000_add_user_username` | User 加 `username`（登录账号） |
| `20260812000000_add_comment_ip` | Comment 加 `ip` + 复合索引 |
| `20260812010000_add_reading_minutes` | Post 加 `readingMinutes` + 存量回填 SQL |

## 五、API 设计

Hono 根应用 `basePath('/api')`，经 `app/api/[[...route]]/route.ts` 的 `handle(app)` 统一接管；NextAuth 的 `/api/auth/[...nextauth]` 路径更具体优先匹配。

### 路由总表

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/posts` | 公开 | 已发布文章分页 `?page&pageSize`（默认 20，上限 50） |
| POST | `/api/posts` | ADMIN | 新建文章（slug 冲突返回 409） |
| GET | `/api/posts/:id` | 公开 | 文章详情（仅已发布） |
| PUT | `/api/posts/:id` | ADMIN | 更新文章（部分字段合并更新） |
| DELETE | `/api/posts/:id` | ADMIN | 删除文章 |
| POST | `/api/posts/:id/like` | 公开+限流 | 点赞 +1，按 IP 60s/1 次 |
| POST | `/api/posts/:id/view` | 公开+限流 | 浏览 +1，按 IP 60s/1 次 |
| GET | `/api/shiyu` | 公开 | 拾语流分页（置顶优先 + 时间倒序） |
| POST | `/api/shiyu` | ADMIN | 新建拾语（自动续号） |
| GET | `/api/shiyu/:id` | 公开 | 单条拾语（仅已发布） |
| PUT | `/api/shiyu/:id` | ADMIN | 更新拾语（显式字段覆盖，其余保持） |
| DELETE | `/api/shiyu/:id` | ADMIN | 删除拾语 |
| GET | `/api/comments` | ADMIN | 全部评论（含文章、作者信息） |
| POST | `/api/comments` | 公开+限流 | 访客提交评论（默认待审核，IP 5min/1 条，内容 ≤100 字） |
| PUT | `/api/comments/:id` | ADMIN | 审核通过 / 转为待审 |
| DELETE | `/api/comments/:id` | ADMIN | 删除评论 |
| GET | `/api/search?q=` | 公开 | 全文搜索（标题/摘要/正文 LIKE） |
| POST/GET | `/api/auth/[...nextauth]` | — | NextAuth 凭证登录 |

### 响应约定
- 成功：JSON 数据实体（POST 返回 201）。
- 错误：`{ error: string }` + 语义化状态码（400 参数、401 未授权、404 不存在、409 slug 冲突、429 限流）。
- 阅/赞接口返回增量后的计数对象。

### 写后缓存刷新
- 文章写操作 → `revalidatePostPaths(slug, tagSlugs)`：刷新 `/`、`/posts`、`/posts/:slug`、`/tags`、`/tags/:tag`。
- 拾语写操作 → `revalidatePath('/shiyu')` + `revalidatePath('/')`（首页台账含拾语计数）。
- 评论写操作 → `revalidatePath('/posts/:slug')`。

## 六、认证与授权

三层防线，由内到外：

1. **数据写操作守卫** `lib/auth.ts#requireAdmin()`
   - 所有 Hono POST/PUT/DELETE 路由入口调用；未登录或非 ADMIN 返回 401 `{ error: '未登录或权限不足' }`。
   - 内部 `getServerSession(authOptions)`，取 JWT 中注入的 `role`。

2. **页面路由守卫** `app/(admin)/layout.tsx`
   - 服务端权威校验：非 ADMIN `redirect('/login')`，管理端页面在服务端就不可达。

3. **中间件** `proxy.ts`（Next.js 16 中 middleware 更名 proxy）
   - `withAuth`：未登录访问 `/dashboard/:path*` 一律跳 `/login`。
   - 角色校验仍由 (admin) layout 兜底，中间件只做第一层门禁。

**登录流程**：`/login` 表单 → `signIn('credentials', { identifier, password })` → `authorize` 按 `username OR email` 查用户 → `bcrypt.compare` 校验 → JWT session 注入 `id` 与 `role`。

**会话**：JWT 策略（`session.strategy='jwt'`），`NEXTAUTH_SECRET` 签名，凭据不落 Cookie。

## 七、渲染策略

| 页面 | 策略 | 实现 |
|---|---|---|
| 首页 `/` | 动态（每次按需重渲染） | `getStats()` + `getRecentPublishedPosts(5)`，写后 revalidate |
| 文章列表 `/posts` | **ISR 60s** | `export const revalidate = 60`；`?page=N` 每页独立缓存 |
| 文章详情 `/posts/[slug]` | **SSG** | `generateStaticParams()` 全量预渲染；写后按需 revalidatePath |
| 标签页 `/tags`、`/tags/[tag]` | ISR | 写后 revalidatePath(`/tags/:tag`) |
| 拾语 `/shiyu` | ISR 60s | 首屏 10 条由服务端传入，翻页走 `/api/shiyu` 客户端加载更多 |
| 搜索 `/search` | 动态 | GET 表单无 JS 依赖，服务端查询 |
| 关于 `/about` | SSG/静态 | 静态内容 |
| 管理后台 `/dashboard/*` | 动态 | 每次实时查库，分页 `?page=N` |

**设计要点**
- `readingMinutes` 入库：列表查询 `select` 只投影卡片字段，不拉正文，避免大字段传输。
- 组合查询统一 `Promise.all` 并发（如详情页 `renderMDX`/`getToc`/`getAdjacentPosts`/`getPublishedComments` 并行）。
- 前台读大量走缓存（SSG/ISR），写操作靠 `revalidatePath` 精准失效，保证数据新鲜度。

## 十、安全设计

| 威胁 | 措施 | 位置 |
|---|---|---|
| 未授权写操作 | `requireAdmin()` 服务端守卫 + (admin) 布局重定向 + proxy 中间件 | `lib/auth.ts`、`app/(admin)/layout.tsx`、`proxy.ts` |
| 密码泄露 | bcryptjs（cost 10）哈希存储；seed 仅测试账号 | `lib/auth.ts`、`prisma/seed.ts` |
| 评论刷屏 | 按 IP 5 分钟限流（DB 查询 `[ip, createdAt]` 索引）+ 内容 ≤100 字 + 默认待审核 | `lib/hono/comments.ts` |
| 阅/赞刷量 | 前端 sessionStorage 会话去重 + 服务端 IP 60s/1 次（进程内滑动窗口） | `components/posts/PostInteractions.tsx`、`lib/hono/rateLimit.ts` |
| 伪造 IP | `getClientIp` 按可信度取：cf-connecting-ip → x-real-ip → x-forwarded-for **最右段**（绝不用可伪造的首段） | `lib/hono/ip.ts` |
| MDX 注入/解析异常 | 邮箱防御性预处理（`<a@b.com>` → markdown 链接，避免被当 JSX）；无自定义远程组件 | `lib/mdx.ts#safeSource` |
| XSS | 正文走 MDX 编译（React 转义）；评论 `whitespace-pre-line` 纯文本展示 | `lib/mdx.ts` |
| 爬虫误爬后台 | `robots.ts` disallow `/dashboard`、`/api/auth`、`/api/` | `app/robots.ts` |

**限流实现说明**：`checkRateLimit` 为**进程内**滑动窗口（`Map<string, number[]>`），本地/单机 Docker 部署可靠；Vercel 多实例下为「尽力而为」，硬限流需换 Redis/DB 表（见演进方向）。

## 十一、性能与体验优化

- **列表轻量**：`readingMinutes` 发布时入库，列表 `select` 投影，绝不拉正文大字段。
- **并发查询**：首页、详情页、后台各页 `Promise.all` 并行拉取。
- **缓存为王**：文章详情 SSG、列表/拾语 ISR 60s、写后 `revalidatePath` 精准失效。
- **Mermaid 懒加载**：`await import('mermaid')` 仅在有图页面才下载。
- **字体本地化**：@fontsource 打包进构建，无第三方字体请求。
- **图片**：`next/image` 的 `fill` + `sizes` + 懒加载（正文 MDX 图例外，用原生 `img` + `loading="lazy"`）；封面域名在 `next.config.ts` `remotePatterns` 白名单。
- **SEO**：metadata / OpenGraph / canonical / JSON-LD BlogPosting / sitemap / robots。
- **暗色主题**：内联脚本同步读 localStorage，防首帧闪白。

### 环境变量（`.env`）
| 变量 | 说明 |
|---|---|
| `DATABASE_URL` | PostgreSQL 连接串 |
| `NEXTAUTH_SECRET` | JWT 签名密钥 |
| `NEXTAUTH_URL` | 站点地址（如 `https://www.puxiaoshuai.top`） |

### 生产部署（Vercel）
1. 静态内容（项目卡）在 `lib/projects.ts` 编辑 → git commit + push → Vercel 自动重部署（约 1 分钟）。
2. 封面图生产切图床（如 `piclink.puxiaoshuai.top`）后，在 `next.config.ts` `images.remotePatterns` 追加域名。
3. 数据库迁移：`prisma migrate deploy`（Vercel 构建前）。

## 十五、局限与演进方向

| 现状 | 演进方向 |
|---|---|
| 搜索用 `LIKE`（`title/excerpt/content contains`） | 生产数据量大时切 PostgreSQL `tsvector` 全文索引 / 分词（代码已留注释 M5-1） |
| 阅/赞、评论限流为**进程内** Map 滑动窗口 | 多实例（Vercel）下换 Redis / DB 表实现硬限流 |
| 封面图用 Unsplash 预设池 + 手动 URL | 生产切图床（已配 `piclink` 域名），后续可做图片上传接口 |
| 拾语配图需手填 JSON 数组 | 后续可接入图床上传 UI |
| `app/(blog)/page.tsx` 首页动态渲染 | 可考虑 Cache Components 或更长 revalidate 进一步降低冷启动 |
| 项目卡为静态数据 `lib/projects.ts` | 数量变大后可迁移进库 + 后台维护 |
| 评论仅文本 | 可扩展 Markdown 评论 / 回复嵌套 |
| 无 OpenSearch / RSS | 可补充 `/rss.xml`、`/feed` 订阅 |
| 无数据备份脚本 | 可加 cron + `pg_dump` 定时备份 |
