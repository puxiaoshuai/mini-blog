# 第 10 节 · 部署运维

> 国内单机服务器最常见的方案：**宝塔面板 + Nginx + PM2 + PostgreSQL**。
> 这一节讲完整的部署流程，以及项目实际踩过的「三个坑」，还有 Nginx 反代的 IP 透传配合第 8 节的限流。

---

## 一、部署拓扑

```
访客浏览器
    │ https
    ▼
Nginx（宝塔）────────── 静态资源（_next/*）直接返回
    │ 反代 http://127.0.0.1:3000
    ▼
Node 进程（PM2 托管 next start，端口 3000）
    │
    ▼
PostgreSQL（5432，仅本机访问）
```

## 二、三个必踩的坑（先记住）

1. **Node 必须 ≥ 20.9** —— Next.js 16 的硬性要求。宝塔装 Node 22 LTS。
2. **`prisma generate` 必须在服务器上跑** —— Prisma 生成物在 `lib/generated/prisma`，被 `.gitignore` 排除，**上传代码不会带过来**，服务器上不跑 generate 就没有 client。
3. **build 阶段就要连数据库** —— 博客页是 SSG/ISR，构建时查库（第 5 节）。顺序错了 build 直接挂。

## 三、完整部署流程（严格按顺序）

### 1. 宝塔装软件
Nginx + Node 版本管理器（或 PM2 管理器）+ PostgreSQL。

### 2. 建数据库
宝塔「数据库」→ 添加 PostgreSQL：
- 库名 `mini_blog`，单独建用户名/密码（**别用 postgres 超级用户**）。

### 3. 上传代码 + 装依赖
```bash
cd /www/wwwroot/blog-project
npm install      # 全量安装！build 需要 devDependencies
```

### 4. 配生产 .env
```env
DATABASE_URL="postgresql://博客用户名:博客密码@127.0.0.1:5432/mini_blog?schema=public"
NEXTAUTH_SECRET="<openssl rand -base64 32 生成的随机串>"
NEXTAUTH_URL="https://www.puxiaoshuai.top"   # 反代进来的是 https，必须写完整
```

> `NEXTAUTH_URL` 写错会导致 NextAuth 回调地址对不上、登录后跳转异常。这是登录类应用上线最常见的坑。

### 5. 依次跑：generate → migrate → seed
```bash
npx prisma generate   # 重新生成 client 到 lib/generated/prisma
npx prisma migrate deploy   # 应用迁移（生产用 deploy 而不是 dev）
npm run db:seed       # 灌入管理员账号 + 初始内容
```

### 6. 构建
```bash
npm run build
```
SSG 页面在这一步全部生成完毕（此时必须能连上数据库）。

### 7. PM2 启动
```bash
pm2 start npm --name mini-blog -- start
pm2 save        # 保存进程列表，重启不丢
pm2 startup     # 开机自启
```

### 8. Nginx 站点配置（关键）
```nginx
server {
    listen 80;
    server_name www.puxiaoshuai.top;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;

        # ★ 真实 IP 透传（配合第 8 节 getClientIp 限流）
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

**为什么必须透传 IP**：不配的话，Node 侧所有请求的 `x-forwarded-for` 都是 Nginx 的地址 `127.0.0.1`，`getClientIp` 拿不到访客 IP → 限流失效、评论查 IP 全撞一起。这是「Nginx 反代 + IP 相关逻辑」的黄金搭配。

## 四、Docker 的定位：只跑本地数据库

`docker-compose.yml` 只包含 PostgreSQL（本地开发用），**不含应用**：

```yaml
services:
  db:
    image: postgres:16-alpine
    container_name: mini-blog-db
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: postgres
      POSTGRES_DB: mini_blog
    ports: ["5432:5432"]
    volumes: [pgdata:/var/lib/postgresql/data]
    healthcheck: { test: ["CMD-SHELL", "pg_isready -U postgres -d mini_blog"], interval: 5s, ... }
volumes: { pgdata: }
```

- `volumes.pgdata` 数据持久化 —— `docker compose down` 不会丢数据。
- `healthcheck` 等 PG 就绪再继续，容器编排常识。
- 生产走宝塔原生 PG，Docker 只是「本地开箱即用」。

## 五、上线后的内容更新闭环

```
写文章（后台 / 或 seed）
   │
   ▼
Hono API 写库 + revalidatePath()
   │
   ▼
Next 重建相关 ISR 路径 → 前台立即可见
```

- **后台写的文章**：Hono 里已调 `revalidatePostPaths`，前台自动刷新。
- **静态内容**（如 `lib/projects.ts` 首页项目）：改文件 → commit → 重新部署（build）。
- **代码注释里的提醒**：`lib/projects.ts` 的注释明确写了「改本文件 → push → 重新部署（约 1 分钟）即生效，无需在线改」。

## 六、常见故障排查表

| 症状 | 原因 | 处理 |
|---|---|---|
| build 报连不上数据库 | build 时查库但库没建/`.env` 没配 | 先建库配 `.env` 再 build |
| 启动报 `PrismaClient is not configured` | 服务器没跑 `prisma generate` | `npx prisma generate` |
| 登录后跳转失败 / 回调错误 | `NEXTAUTH_URL` 写错 | 改成 https 完整域名 |
| 图片报 hostname not configured | `next.config.ts` 没加图床域名 | 追加 `remotePatterns` 后重新部署 |
| 限流全判成同一 IP / 评论限流异常 | Nginx 没透传真实 IP | 加 `X-Real-IP` / `X-Forwarded-For` |
| 页面显示旧内容 | SSG 缓存未刷新 | 确认写操作后 revalidatePath 是否触发；或手动重新部署 |

## 七、本节小结

- **方案**：宝塔 Nginx 反代 → PM2 托管 Next → 本机 PG。
- **三个坑**：Node ≥ 20.9、服务器跑 `prisma generate`、build 前连库。
- **顺序**：建库 → `.env` → install → generate → migrate → seed → build → PM2。
- **Nginx 透传 IP** 是限流生效的前提。
- **Docker 只跑本地 DB**，生产用宝塔原生 PG。
- 内容更新靠「写库 + revalidatePath」的 ISR 闭环，静态内容靠重新部署。
