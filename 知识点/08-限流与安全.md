# 第 8 节 · 限流与安全

> 博客有访客可写的入口：评论、点赞、浏览。任何公网接口都会被刷。
> 这一节讲客户端真实 IP 提取（信任链）、内存滑动窗口限流、以及前端去重 + 服务端防线的组合拳，顺便过一遍其他安全细节。

---

## 一、客户端真实 IP 提取（lib/hono/ip.ts）

要按 IP 限流，先得拿到"真实 IP"。网站前面是 **Nginx 反代**（或 Cloudflare），`request` 里的 `c.req.header` 必须按**可信度逐级尝试**：

```ts
export function getClientIp(c: Context): string | null {
  const cf = c.req.header("cf-connecting-ip");     // 1. Cloudflare 专用头
  if (cf) return cf.trim();
  const real = c.req.header("x-real-ip");          // 2. Nginx $remote_addr 直填
  if (real) return real.trim();
  const fwd = c.req.header("x-forwarded-for");     // 3. 取最右一段
  if (fwd) {
    const parts = fwd.split(",").map((s) => s.trim()).filter(Boolean);
    if (parts.length) return parts[parts.length - 1];
  }
  return null;
}
```

**为什么这个顺序**（这是最容易写错的地方）：

| 头 | 谁写的 | 可信度 | 说明 |
|---|---|---|---|
| `cf-connecting-ip` | Cloudflare | 仅在用了 CF 时可信 | 没用 CF 时客户端可伪造，但这里优先取它也没错（CF 会覆盖） |
| `x-real-ip` | Nginx `$remote_addr` 直填 | 高 | 客户端伪造不了，无 CDN 时最可信 |
| `x-forwarded-for` | Nginx `$proxy_add_x_forwarded_for` 追加 | 取**最右**才可信 | 最左是客户端可伪造的，**绝不能取首段** |

> 经典安全漏洞：`x-forwarded-for` 取**第一个**值 = 客户端随便传个假 IP 就能绕过限流。必须取**最右一段**（那是 Nginx 追加上去的真实对端）。
> 部署时 Nginx 要配好透传（第 10 节）：`proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`

## 二、内存滑动窗口限流（lib/hono/rateLimit.ts）

```ts
const buckets = new Map<string, number[]>();   // key → 时间戳列表

export function checkRateLimit(key: string, windowMs: number, max: number): number {
  const now = Date.now();
  // 只保留窗口内的历史，顺便防 Map 膨胀
  const list = (buckets.get(key) ?? []).filter((t) => now - t < windowMs);

  if (list.length >= max) {
    buckets.set(key, list);
    return Math.max(1, Math.ceil((windowMs - (now - list[0])) / 1000));  // 需等待秒数
  }
  list.push(now);
  buckets.set(key, list);
  return 0;   // 放行
}
```

原理：
- 每个 key（如 `like:<ip>:<postId>`）存一个时间戳数组，代表"最近几次操作的时间"。
- 新请求来，先丢掉窗口外的旧时间戳（天然滑动窗口）。
- 若窗口内数量 ≥ 上限，返回**还需等多少秒**（给用户友好的提示）；否则记录并放行。

**诚实备注**（代码注释里也写了）：这是**单实例内存**实现。
- 本地 / 单机 Docker：可靠。
- Vercel 等 serverless 多实例：每实例各自计数，属"尽力而为"，硬限流要换 Redis / DB 表。

## 三、限流实战：三种场景

### 1. 评论：5 分钟一条（查 DB）

评论用「数据库查最近一条」来限——因为评论本身落在 DB，直接查更简单且跨实例有效：

```ts
const ip = getClientIp(c);
if (ip) {
  const recent = await prisma.comment.findFirst({
    where: { ip, createdAt: { gte: new Date(Date.now() - RATE_WINDOW_MS) } },
    orderBy: { createdAt: "desc" },
  });
  if (recent) {
    // 算出剩余秒数，格式化「X 分 Y 秒」提示用户
    const remainSec = ...;
    return c.json({ error: `评论太频繁了，请 ${label} 后再试` }, 429);
  }
}
```

> 用 DB 而不是内存桶，是因为评论接口跨实例一致性更重要，且 `Comment` 表本来就有 `@@index([ip, createdAt])` 复合索引，查询很便宜。

### 2. 点赞 / 浏览：1 次/分钟（内存桶）

高频轻量操作，用内存滑动窗口：

```ts
const ip = getClientIp(c);
const wait = ip ? checkRateLimit(`like:${ip}:${id}`, RATE_WINDOW_MS, RATE_MAX) : 0;
if (wait > 0) return c.json({ error: `操作太频繁，请 ${wait} 秒后再试` }, 429);
```

key 设计成 `like:<ip>:<postId>`，**同一 IP 对不同文章各算各的**——用户点赞不同文章不该被互相牵连。

### 3. 前端去重 + 服务端防线（双保险）

点赞/浏览**只在浏览器层面拦截远远不够**（脚本可绕过），但前端先挡一层能省服务器资源：

```tsx
// PostInteractions.tsx —— 浏览按会话去重
useEffect(() => {
  const key = `viewed_${postId}`;
  if (sessionStorage.getItem(key)) return;      // 本会话看过了，不再上报
  fetch(`/api/posts/${postId}/view`, { method: "POST" })...
    .then((d) => { sessionStorage.setItem(key, "1"); });  // 成功后标记
}, [postId]);

// 点赞防连点
async function like() {
  if (busy || liked) return;   // busy 防连点，liked 防重复
  ...
}
```

架构图：
```
浏览器（sessionStorage 去重 + disabled 防连点）
        │
        ▼
Hono API（IP 限流，内存桶 / DB 查）
        │
        ▼
Prisma（increment 原子自增）
```

## 四、其他安全细节清单

1. **密码 bcrypt** —— 登录密码 `bcrypt.hash` 后存储，比对用 `bcrypt.compare`；无注册入口，管理员 seed 创建。
2. **双防线鉴权** —— `(admin)` layout 拦页面 + `requireAdmin()` 拦 API（第 4 节）。
3. **输入校验** —— 所有字段 `trim()` 后校验非空/长度；评论 100 字上限；`page/pageSize` 数值钳制。
4. **唯一冲突友好化** —— Prisma `P2002` 转成 409「slug 已存在」，不暴露原始错误。
5. **JSON 解析防御** —— `c.req.json()` 包 try/catch，非法体 400。
6. **robots 禁爬管理区** —— `robots.ts` 里 `disallow: ["/dashboard", "/api/", ...]`（第 9 节）。
7. **访客身份最小化** —— 访客评论按邮箱 find-or-create `User`，**只存显示名，无密码**，不可登录（`password: null`）。
8. **评论默认待审核** —— `published: false`，管理员后台通过后才展示，防止垃圾评论上墙。

## 五、本节小结

- **IP 提取**：`cf-connecting-ip` → `x-real-ip` → `x-forwarded-for` 最右段，按可信度递减。
- **内存滑动窗口**：时间戳数组 + 窗口过滤 + 返回等待秒数，轻量够用；多实例要换 Redis。
- **三种限流姿势**：评论查 DB（跨实例可靠）、阅/赞内存桶（高频轻量）、前端去重做第一道防线。
- **安全基操**：bcrypt、双防线鉴权、输入校验、P2002 转 409、评论待审核。
