# 第 5 节 · 渲染策略：SSG / ISR / SSR

> 博客是「读多写少」的内容站，渲染策略直接决定性能和部署体验。
> 这一节讲项目里三种策略分别用在哪、`generateStaticParams` / `revalidatePath` 怎么配合增量刷新。

---

## 一、三种策略一句话

| 策略 | 何时渲染 | 何时更新 | 适合 |
|---|---|---|---|
| **SSG**（静态生成） | 构建时 | 重新部署 | 几乎不变的内容 |
| **ISR**（增量静态再生成） | 构建时 + 过期后后台重建 | `revalidate` 秒数 / `revalidatePath` 触发 | 变化不频繁、可接受短暂延迟 |
| **SSR**（服务端渲染） | 每次请求 | 每次请求 | 强实时、依赖用户态 |

Next 的默认约定：**能静态就静态**。页面若没有动态 API，默认就是 SSG/ISR。

## 二、项目里的分布地图

| 页面 | 策略 | 依据 |
|---|---|---|
| 首页 `/` | SSG（构建时生成） | 构建时查库渲染 |
| 文章列表 `/posts` | SSG | 同上 |
| 文章详情 `/posts/[slug]` | SSG（`generateStaticParams` 枚举所有 slug） | 每个 slug 一篇 HTML |
| 标签 `/tags`、`/tags/[tag]` | SSG | 同上 |
| 拾语 `/shiyu` | **ISR**（`export const revalidate = 60`） | 高频更新，60s 重建 |
| 关于、搜索 | SSG / SSR 混合 | 搜索按 query 实时查库 |
| 后台 `/dashboard` | **SSR（每次请求鉴权）** | 必须实时校验 session |

## 三、关键 API 逐个讲

### 1. `generateStaticParams`：枚举动态路由

文章详情页 `posts/[slug]/page.tsx`：

```tsx
export async function generateStaticParams() {
  const posts = await getPublishedPostRefs();   // 只查 slug + createdAt
  return posts.map((p) => ({ slug: p.slug }));
}
```

构建时把所有已发布文章的 slug 枚举出来，**每篇预渲染成静态 HTML**。配合 `getPostBySlug` 在页面里查正文渲染。

> 部署关键推论：**build 时就要连数据库**。因为这些查询都在构建阶段跑（第 10 节的"三坑"之一）。

### 2. 双语言静态生成

根布局 `app/[locale]/layout.tsx` 里：

```tsx
export function generateStaticParams() {
  return routing.locales.map((locale) => ({ locale }));
}
```

返回 `['zh', 'en']` → `/zh` 和 `/en` 两套页面**各自静态生成**，访客访问不查库直接命中 HTML。

### 3. `generateMetadata`：构建时生成 <head>

```tsx
export async function generateMetadata({ params }): Promise<Metadata> {
  const post = await getPostBySlug(slug);
  return {
    title: post?.title ?? t("title"),
    description: post?.excerpt,
    alternates: { canonical: `/${locale}/posts/${slug}` },
    openGraph: { title, description, type: "article", images: [coverImage] },
  };
}
```

SEO 信息在构建时随页面一起算好，用户访问零开销。

### 4. ISR：`export const revalidate`

拾语页高频更新，用时间维度兜底：

```tsx
// app/[locale]/(blog)/shiyu/page.tsx
export const revalidate = 60;   // 60 秒后台重建一次
```

访问时若缓存过期，后台异步重建再返回新页；用户永远拿到"最多 60 秒旧"的页面，且不阻塞请求。

### 5. `revalidatePath`：写操作后精准刷新

时间维度兜底（60s）之外，**写操作后要立即让前台更新**，用 `revalidatePath`：

`lib/revalidate.ts`
```ts
import { revalidatePath } from "next/cache";

export function revalidatePostPaths(slug: string, tagSlugs: string[] = []) {
  revalidatePath("/");                 // 首页
  revalidatePath("/posts");            // 文章列表
  revalidatePath(`/posts/${slug}`);    // 本文详情
  revalidatePath("/tags");             // 标签页
  for (const tag of tagSlugs) revalidatePath(`/tags/${tag}`);  // 相关标签
}

export function revalidateShiyuPaths() {
  revalidatePath("/shiyu");
  revalidatePath("/");                 // 首页台账含拾语计数
}
```

Hono 里写操作成功后调用：
```ts
// 新建/更新/删除文章后
revalidatePostPaths(post.slug, tagSlugs);
// 评论审核后
revalidatePath(`/posts/${existing.post.slug}`);
// 拾语增删改后
revalidatePath("/shiyu"); revalidatePath("/");
```

**为什么评论、拾语改完要刷前台**：它们是 ISR/SSG 页面，改了数据库但 HTML 还是旧的，必须主动触发重建，否则用户看不到新评论。

### 6. 客户端写操作 + `router.refresh()`

评论区、点赞这类交互是 client component，写完用 `router.refresh()` 重新拉取服务端数据：

```tsx
const res = await fetch("/api/comments", { method: "POST", body: JSON.stringify({...}) });
if (res.ok) {
  setMessage(t("submitted"));
  router.refresh();   // 重新执行当前页的 Server Component，拿到新评论
}
```

`router.refresh()` 不重载整个页面，而是**让当前路由的 Server Component 重新跑一遍**——服务端数据一变，UI 同步更新。配合 Hono 写操作 + `revalidatePath`，形成「写 DB → 刷新 ISR → 重新渲染」的闭环。

## 四、并行查询优化

首页一次性渲染多处数据，用 `Promise.all` 并行（这是 Next 官方推荐写法，避免串行瀑布）：

```tsx
const [stats, posts] = await Promise.all([
  getStats(),                 // 四格统计
  getRecentPublishedPosts(5), // 最近文章
]);
```

## 五、一个易错点：为什么 SSG 页面"看不到"新数据

经典困惑：**数据库有数据了，页面还是旧的**。

原因：SSG 页面的 HTML 是构建时生成的，直接走 CDN/静态文件，**不查库**。要更新必须：
1. 重新部署（全量重建），或
2. 手动触发 `revalidatePath`（项目里 Hono 写操作已在做），或
3. 该页配置了 `revalidate` 自动到期重建。

项目策略：**内容页（文章/标签）= 写操作后主动 revalidate；拾语页 = 写操作主动 revalidate + 60s 到期兜底**。双保险。

## 六、本节小结

- **SSG**（文章、标签、双语言）→ 构建时生成，访问零查询。
- **ISR**（拾语，`revalidate=60`）→ 时间兜底，后台异步重建。
- **`revalidatePath`** → 写操作后精准刷新相关路径，保证前台立即可见。
- **`generateStaticParams`** → 枚举 slug / locale，动态路由静态化。
- **`router.refresh()`** → 客户端写操作后重跑 Server Component。
